# AT-SPI accessibility automation (tier 2)

> Read this before any non-trivial desktop-app automation. AT-SPI is the
> fastest, most reliable way to interact with native Linux GUIs.

## Why AT-SPI beats screenshots

Reading a screenshot and reasoning about pixels is slow and brittle: the model
has to find the element, infer its bounds, guess whether it's clickable, then
send a coordinate click that breaks if the window moves a pixel.

AT-SPI (Assistive Technology Service Provider Interface) is the same D-Bus
protocol screen readers use. GTK, Qt, and Electron (with a flag) register every
window, button, text field, menu item, label, and table cell as a structured
*accessible* object exposing:

- a **role** (`push button`, `text`, `menu item`, `frame`, `list`, ...)
- an accessible **name** (e.g. `"Save"`, `"Search"`)
- a **state set** (`focused`, `sensitive`, `checked`, `editable`, ...)
- screen-space **bounds** `[x, y, w, h]`
- interfaces: `Action` (invoke), `Text` / `EditableText` (read/write),
  `Component` (focus, geometry), `Selection`, `Table`, ...

You query that tree directly — no OCR, no coordinate guessing. Invoking an
element via its `Action` interface doesn't even move the mouse and works if the
window is occluded.

## The priority ladder (recap)

1. **Browser DOM/CDP** (`browser.py`) — for anything inside a browser tab.
   CDP gives DOM + selectors + JS, which is strictly more capable than
   accessibility for web content.
2. **AT-SPI** (this module) — for native desktop app widgets.
3. **Hyprland IPC** (`hyprland.py`) — windows/workspaces/monitors as a whole.
4. **OCR** (`ocr.py`) — canvases, images, PDFs, games, remote desktops.
5. **Coordinate input** (`input.py`) — last resort.

Only drop a tier when the higher one genuinely can't see the element.

## How it's wired in this skill

`gi.repository.Atspi` (from `python-gobject` + `at-spi2-core`) lives in
**system** site-packages. The CLI runs under `uv run`, whose isolated venvs
deliberately don't see system site-packages — so importing `gi` from
`accessibility.py` directly fails silently.

The fix is a worker split:

```
cli.py (uv run, python 3.12)
  └─ accessibility._call_worker(action, **kwargs)
       └─ subprocess: /usr/bin/python3 _atspi_worker.py <action> '<json>'
            └─ import gi.repository.Atspi   ✓ (system site-packages)
            └─ prints exactly one JSON line, exits
       └─ json.loads(last stdout line)
```

One process spawn per call (~tens of ms). That's negligible next to the latency
of screenshot+OCR+vision-reasoning that AT-SPI replaces.

## CLI

| Action | What it does |
|--------|--------------|
| `a11y check` | Diagnostics: import state, gsetting, registered app count, hints. |
| `a11y apps` | List every app on the AT-SPI desktop (index, name, role, pid). |
| `a11y tree [--app A] [--depth N]` | Nested tree as JSON. `--app` filters by substring. |
| `a11y find --app A --role R --name N` | Search by role and/or name substring; returns matches with `path` + `bounds`. |
| `a11y click --path 0,2,1` | Invoke the element at that path (Action iface, else coordinate click). |
| `a11y type --path P --name "text"` | Set the field's text (EditableText, else focus+type). |
| `a11y read --path P` | Read the element's text via the Text interface. |

`--path` is a comma-separated list of child indices from the desktop root
(`[app_index, child, child, ...]`). Every `find` / `tree` result includes the
`path` you need to act on it.

## The standard flow

```bash
# 1. Confirm the app is registered
linux-automation a11y apps

# 2. Find the element you want (by role and/or name)
linux-automation a11y find --app firefox --role "push button" --name "Save"
# -> [{"name": "Save", "role": "push button", "path": [3, 0, 2, 5], "bounds": [...], ...}]

# 3. Act on it by path
linux-automation a11y click --path 3,0,2,5
linux-automation a11y type  --path 3,0,2,1 --name "hello@example.com"
linux-automation a11y read  --path 3,0,2,0
```

For Python callers, `accessibility.wait_for(app=, role=, name_contains=, timeout=)`
polls `find` until the element appears — useful after triggering an async action
(opening a dialog, navigating, etc.).

## Common roles

`push button`, `toggle button`, `check box`, `radio menu item`, `entry` / `text`,
`password text`, `label`, `menu`, `menu item`, `list`, `table`, `table cell`,
`combo box`, `frame` (top-level window), `dialog`, `tool bar`, `status bar`,
`scroll pane`, `tree`, `tree item`. Run `a11y tree --app <name> --depth 3` to
see the exact roles an app exposes.

## Why an app doesn't register with AT-SPI

If `a11y apps` doesn't list your app, it isn't wiring up its accessibility
bridge. Common causes:

| App type | Fix |
|----------|-----|
| **GTK** | Usually automatic once `toolkit-accessibility=true`. Apps started *before* you enabled the gsetting won't appear until restarted. |
| **Qt** | Needs `QT_ACCESSIBILITY=1` in the environment at launch. |
| **Electron** (VS Code, Slack, Discord, Obsidian) | Launch with `--force-renderer-accessibility`. |
| **Terminal emulators** (kitty, alacritty, foot) | Generally **never** expose a useful tree — the content is one text-grid widget. Read terminal content directly (you're usually driving the terminal anyway), or OCR as a last resort. |
| **Flatpak / sandboxed** | May need accessibility permissions granted in the portal. |
| **Chrome / Firefox** | Use CDP (tier 1) instead — the page DOM is richer than the a11y tree. |

Verify the global prerequisites with `linux-automation a11y check` or
`linux-automation doctor`.

## Debugging

- `linux-automation a11y check` — confirms the import works under system python,
  the gsetting is on, and reports the registered app count.
- If `check` shows `desktop_app_count <= 1` but you have apps open, they were
  likely started before accessibility was enabled — restart them.
- For interactive inspection, install `accerciser` (`sudo pacman -S accerciser`)
  — a GUI browser over the same AT-SPI tree, handy for finding the exact path
  and role of an element.
- `a11y tree --app X --depth 8` dumps the whole subtree to JSON; grep it for
  the name you're looking for.

## What this skill intentionally does NOT use

- **`pyatspi`** (the legacy `python-atspi` package). It's a separate, less
  maintained binding that isn't installed here. The GObject-introspection
  binding `gi.repository.Atspi` covers the same D-Bus protocol and is already
  present via `python-gobject` + `at-spi2-core`. Adding pyatspi gains nothing.
- **Newton** — the in-development Wayland-native accessibility architecture. Not
  shipped; AT-SPI remains the production stack today.
